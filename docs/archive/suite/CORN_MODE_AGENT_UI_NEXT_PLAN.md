> 文档状态：下一步执行计划 v1.0
>
> 制定日期：2026-08-22
>
> 适用项目：`dsh-corn-bench`
>
> 当前核验基线：`6b448ea58a0d`，`package.json` 版本 `0.17.4`，工作区模型已进入 `version:3`
>

## 1. 文档目的与优先级

这是一份独立的增量计划，用来补全正在执行的主计划尚未充分定义的四个部分：

1. 把安装后提供的 Agent 预设从「台架模式」正式更名为「Corn模式」，并建立可靠的预设升级机制。
2. 让 Corn模式 Agent 与调试、上位机、侧边栏使用同一份现场状态，Agent 的现场操作在传统界面中完整可见。
3. 删除价值重复的「总览」Tab，把必要信息迁回调试、上位机和统一协作状态条。
4. 重构上位机多连接导航以及右侧栏「监视、曲线、告警、串口报文」。

本文档对上述四个主题具有优先解释权；主计划的其他范围、Windows 目标和非目标保持不变。主计划当前正在实施时，不并行修改相同文件；以当前阶段合入后的最新干净提交作为本计划真正开工基线。

## 2. 已确认的产品决策

以下事项不再作为开放问题：

| 事项 | 决策 |
|---|---|
| Agent 预设显示名称 | 使用「Corn模式」 |
| 预设内部 ID | 继续使用 `corn-bench`，避免破坏已存在 Session 和用户目录 |
| 独立「总览」Tab | 删除，不再建设第二套摘要页面 |
| 上位机多连接导航 | 使用连接级内部标签栏，下面只呈现当前连接内容 |
| 连接标签身份 | 使用稳定 `connectionId`；界面显示“连接名称 · COM/端点” |
| 设备导航 | 放在当前连接下的设备列表/设备树，不再叠加一排无限横向标签 |
| 侧栏「点表」 | 改名为「监视」，不承担完整点表配置 |
| 侧栏「曲线」 | 保留，作为聊天过程中的短窗口快速观察 |
| 侧栏「告警」 | 保留，作为当前异常和快速定位入口 |
| 「串口日志」 | 改为「串口报文」，从调试页迁入侧边栏 |
| 串口报文选择 | 可以选择 `全部串口` 或具体 COM；内部仍关联 `connectionId` |
| 协议报文与原始串口数据 | 同一侧栏内分模式展示，底层采集和占用规则保持分离 |
| Agent 配置修改 | 先生成草稿和差异，不能静默覆盖界面配置 |
| 高影响操作 | 写点、下载、复位继续要求明确目标和人工确认 |

## 3. 当前代码现状

### 3.1 已经具备的基础

- 工作区已经实现 `connections[] + devices[] + points[]` 的 v3 模型。
- 已有连接、设备、点位、轮询、帧缓存、任务、时间线和 Session 绑定基础。
- 上位机已经能够创建多个连接和设备，并进行 COM 冲突校验。
- `corn_bench` 已经提供状态、工程、编译、读取、写入、连接、点位和人工步骤等统一工具入口。
- Agent 发起的写点已经有界面确认卡和回读流程。
- `dsh-better-sidebar` 已承载点表、曲线、告警和工程侧栏。

### 3.2 当前主要缺口

#### Agent 预设

- 源码仍使用「台架模式」名称。
- 本机已安装预设可能保留更早的提示词；当前依赖整句文本匹配的升级方式无法覆盖所有旧版本。
- 预设提示词仍偏向“编码 Agent 加一个 Modbus 工具”，没有完整描述连接、设备、点位、报文、界面回显和证据责任。
- 官方 Harness 的用户预设是从 `standard` 复制出的快照，复制后会与后续官方 `standard` 漂移；当前没有安全的重建或提示流程。
- 工具仍存在依赖“当前连接/当前设备”的兼容入口，与多连接下的显式目标要求没有完全收口。

#### 总览

- 总览重复展示调试页和上位机页已经拥有的信息。
- 总览部分逻辑仍读取旧式单连接字段，继续扩展会形成第三套界面状态映射。
- 用户真正需要的是在当前任务页面看到状态和待办，而不是离开工作页面查看摘要。

#### 上位机连接区

- 多个连接当前仍容易纵向堆叠。
- 连接管理、当前连接配置、设备和点位之间的视觉层级不够强。
- 非当前连接上的 Agent 任务、报警和待确认缺少连接标签级提示。

#### 侧边栏

- 「点表」与上位机主页面点表重复，且仍包含旧式 `conn/polling` 访问和不完整目标信息。
- 曲线只有短窗口基础绘制，没有质量断点、区间选择、缩放、导出和 Agent 证据引用。
- 告警只是时间线中的 `alarm/alarm-clear` 事件列表，还不是激活、恢复、确认完整状态模型。
- 串口文本监视在调试页；协议请求/响应又在上位机报文区，用户难以持续观察并区分两者。

## 4. 外部调研结论

### 4.1 正常上位机与串口工具的共同模式

成熟工具给出的共同信号是：

- 连接是独立工作上下文，不应把多个连接的配置、点位和报文全部堆在一个长页面。
- 一个连接可以包含多个 Unit ID；实时监控必须保留连接、设备和地址三层身份。
- 通信流量窗口只展示本工具实际发送和接收的内容，不能伪装成物理总线嗅探器。
- 原始字节查看、快速曲线和完整项目配置是不同工作模式，应共享数据但不要混为一种界面。
- 趋势至少需要序列选择、缺失值、缩放/平移和区间统计。
- 报文需要原始值、解码、方向、耗时、状态和请求/响应关联。

参考依据：

- Modbus Poll 使用多个监视窗口同时查看不同 Slave ID 或数据区，并提供通信流量和实时曲线。
- Modbus Poll 明确说明其通信窗口只显示自身发送和接收的数据，不是总线嗅探器。
- Serial Studio 把原始 Console、快速绘图和项目化解析区分成不同模式，并支持多数据源。
- ModbusScope 提供多设备、缩放、标记、区间统计和 CSV 导出。
- ModbusLens 把实际线上的原始字节、解码值、延迟和状态放在同一事务证据中。

### 4.2 DeepSeek Harness 预设机制的约束

官方仓库确认：

- Session 创建后预设固定，不能把已经产生历史的 Session 热切换到另一个预设。
- 用户预设通过复制完整目录创建；复制是快照，会与官方 `standard` 后续更新产生漂移。
- Agent 作用域可以注册自己的系统提示区段和工具定义。
- 工具 schema 会进入模型请求，过长且长期不变的 schema 会持续占用上下文；提示规则、工具参数和大体量现场数据应该分层。
- Harness 已提供 `defineTool()` 和运行时参数校验机制，不需要插件再实现一套通用工具校验器。

### 4.3 X 检索结果

已使用 `Serial Studio`、`Modbus Poll`、`Modbus RTU monitor`、`deepseek-harness agent preset` 等组合检索 X 的公开索引。没有得到可稳定核验、并且比官方文档或开源仓库更有工程价值的帖子。

因此本计划不使用 X 帖子作为功能或技术选型依据。后续若获得具体账号或帖子链接，再补充为用户反馈信号，不替代官方协议、官方仓库和可复现代码证据。

## 5. 不重复造轮子的技术采用表

| 需求 | 采用或复用 | 决策 | 原因 |
|---|---|---|---|
| Harness 预设与 Session 规则 | 官方 `agent-presets`、作用域 system-prompt section | 采用 | 遵循官方生命周期，不另建 Agent 框架 |
| Agent 工具定义与校验 | Harness `defineTool()` | 采用 | 避免手写一套 schema 校验和错误路径 |
| 修改用户预设 YAML | `yaml` 的 Document API | 采用 | 可解析、修改并保留注释和空行，替代脆弱字符串替换 |
| Modbus RTU/TCP | 现有 PyModbus | 继续采用 | 已接入且支持客户端、服务端、RTU/TCP 和标准功能码 |
| Windows COM 枚举与原始串口 | 现有 PySerial | 继续采用 | 可返回 COM、描述、VID/PID/序列号等信息 |
| COM 占用 | 现有插件端口锁 + Windows 独占事实 | 继续采用 | 不再引入 Node 原生串口依赖造成 Windows 打包风险 |
| 大量报文列表 | `@tanstack/react-virtual` | 候选采用，先做打包验证 | 适合大量变长列表，避免自写虚拟滚动 |
| 实时时序曲线 | `uPlot` | 候选采用，先做质量断点原型 | 体积小、支持缺失值、缩放、游标和实时更新 |
| 配置草稿差异 | RFC 6902 + `fast-json-patch` | R3 采用 | 使用标准补丁表示，支持 compare、validate 和 apply |
| 审批请求哈希 | Node `crypto` | 继续采用 | 标准库足够，不增加依赖 |
| 侧边栏容器 | 已安装 `dsh-better-sidebar` | 继续采用 | 不另造停靠窗口或侧栏系统 |
| 连接标签 | Harness 现有 UI 风格与本插件 React/CSS | 复用现有原语 | 只实现领域相关导航；不为一条标签栏引入整套 UI 框架 |
| Serial Studio、ModbusScope、QModMaster 代码 | 只参考交互 | 不直接复制 | 许可证、语言和架构不适合直接嵌入本插件 |

所有新增依赖在落地前必须完成许可证、锁定版本、Windows 打包和 bundle 大小检查。候选库原型不通过时，可以暂缓功能，但不能悄悄退回未经性能验证的自写大数据控件。

## 6. 目标信息架构

删除「总览」后，用户可感知结构调整为：

```text
Session 主区域
├── 对话
├── 调试
└── 上位机
    ├── 连接标签栏
    ├── 当前连接状态与设备列表
    ├── 当前设备点表与实时值
    └── 当前连接报文分析

Session 右侧栏
├── 监视
├── 曲线
├── 告警
├── 串口报文
└── 工程

跨页面共享
├── Corn模式 Session 绑定
├── Agent 任务/来源/进度
├── 待确认与人工步骤
└── 时间线和证据引用
```

职责原则：

- 调试页负责工程、编译、产物、下载和设备调试输出。
- 上位机页负责连接、设备、点位、读写和完整通信诊断。
- 侧边栏负责用户在对话或调试过程中持续观察，不复制完整配置能力。
- Agent 联动是贯穿各页面的能力，不新增一个“AI 页面”。

## 7. Corn模式预设改造

### 7.1 命名迁移

- UI 名称、预设元数据、README、安装提示、设置提示和测试统一改为「Corn模式」。
- `PRESET_ID` 保持 `corn-bench`。
- `$DSH_HOME/.agent-presets/corn-bench/` 路径保持不变。
- 已存在 Session 继续使用原预设组合；更名主要影响预设列表和后续新建 Session。
- 禁止通过创建第二个 `corn-mode` 目录实现更名，避免用户看到两个功能相同的预设。

### 7.2 提示词职责重新分层

不再把全部 Corn 行为规则硬编码进复制出来的 `standard` persona。目标分为三层：

1. `standard` 提供通用编码 Agent 能力。
2. `dsh-corn-bench` 在 Agent 作用域注册独立的 `corn-bench:guidance` 提示区段。
3. 实时现场数据继续通过 `corn_bench` 工具和结构化通知按需获取。

这样插件升级时，Corn 规则随插件代码更新，不再依赖匹配并替换某一句旧 persona。预设文件只负责挂载插件 Agent 行和展示名称。

### 7.3 Corn Agent 稳定规则

提示区段必须简短、稳定，并明确以下行为：

- 当前环境是真实或仿真的本地设备台架。
- 工程、连接、设备、点位、值、报文和任务必须通过工具确认。
- 不要求每个任务固定执行 `status → map`；根据问题查询最小必要现场信息。
- 涉及现场对象时引用稳定 ID，不用界面当前焦点代替目标。
- 上位机和调试页面是用户可操作的同一现场，Agent 操作必须进入任务、时间线和页面回显。
- 普通后台读取不得强制切换用户当前界面；只有明确聚焦请求才改变界面焦点。
- 配置修改先创建草稿，展示差异和冲突后由用户应用。
- 写点、下载、复位等高影响操作必须经过审批，并绑定端点指纹和配置版本。
- 诊断结论必须引用编译、日志、点值、质量、报文、趋势区间或操作结果。
- 不把高频点值和大量报文持续塞入系统提示。

### 7.4 预设安装与升级机制

增加插件自有的预设状态文件，例如：

```json
{
  "owner": "dsh-corn-bench",
  "presetSchemaVersion": 2,
  "basePresetId": "standard",
  "pluginRowId": "corn-bench-tools",
  "lastManagedAt": "2026-08-22T00:00:00.000Z"
}
```

升级规则：

- 使用 YAML Document API 定位 `id: corn-bench-tools`，不再使用字符串拼接检测结构。
- 插件只修改自己拥有的行、元数据和状态文件。
- 如果旧 persona 完全匹配已知 Corn 历史版本，将其恢复为对应标准 persona，Corn 规则改由插件提示区段提供。
- 如果 persona 有无法确认归属的用户修改，不自动覆盖；保留内容并显示“预设需要人工检查”。
- 重复启动必须幂等，不产生第二个工具行、第二段提示或重复元数据。
- 官方 `standard` 基础发生变化时，不静默重建整个用户预设。提供“基础预设有更新”的诊断和安全重建入口；重建前备份旧目录并展示差异。
- 外部同名但没有插件 ownership 标记的预设继续拒绝覆盖。

### 7.5 Agent 动作权限矩阵

| 动作 | 默认行为 | 界面要求 |
|---|---|---|
| 查询状态、值、报文、日志 | 可直接执行 | 记录查询来源；大量查询显示任务摘要 |
| 发起编译、只读验证 | 可直接执行 | 调试页显示目标、进度、取消和结果 |
| 请求界面聚焦或高亮 | 可执行 | 不改变设备状态；页面提供返回原焦点 |
| 创建监视组、快照 | 可直接创建临时对象 | 明确标记 Agent 来源，可删除 |
| 创建连接/设备/点位修改 | 只生成草稿 | 显示差异、冲突和影响范围 |
| 应用配置草稿 | 需要确认 | 绑定配置版本；漂移后失效 |
| 写点、下载、复位 | 需要确认 | 显示完整目标、请求哈希、端点指纹和回读/验证 |
| 原始串口发送 | 初期不开放给 Agent | 后续单独设计命令白名单和确认 |

## 8. Agent 工具契约补全

### 8.1 近期继续保留统一入口

先保留 `corn_bench`，避免安装后向模型暴露大量零散工具。内部 action 按领域分组，工具说明不重复预设中的长篇行为规则。

当 schema 超过约 8KB、模型选错 action 的人工验收失败率超过 5%，或同一轮频繁重试参数时，再评估拆为：

- `corn_bench_debug`
- `corn_bench_modbus`
- `corn_bench_ui`

拆分不是本计划首个交付物。

### 8.2 必须补齐的目标参数

- `status` 返回连接列表、设备摘要、当前 HMI 焦点、侧栏焦点、任务和待确认摘要，不直接返回大量帧和历史值。
- `read` 的点位读取至少携带 `connectionId + deviceId + pointId`。
- 临时裸地址读取携带 `connectionId + deviceId + area + address + count`。
- `write` 只允许稳定 `pointId`，并同时验证所属连接和设备。
- `frames` 需要 `connectionId`；单帧需要 `frameId` 或 `transactionId`。
- `focus` 显式携带页面和目标对象，不把“当前连接”作为写入目标。
- 所有返回值统一携带 `workspaceId/sessionId/taskId`，现场对象按需携带稳定 ID。

### 8.3 工具实现复用 Harness 能力

- 使用官方 `defineTool()` 生成和校验参数。
- 输出继续使用结构化 JSON，不把整段日志拼成工具描述。
- 为错误提供稳定错误码，例如 `PORT_IN_USE`、`TARGET_REQUIRED`、`DEVICE_DISABLED`、`ENDPOINT_DRIFT`、`STALE_VALUE`、`WRITE_READBACK_MISMATCH`。
- 工具契约生成测试与文档快照必须同步，避免实现、提示词和 README 三套描述漂移。

## 10. 上位机多连接标签栏

### 10.1 页面结构

```text
[全部连接] [冷机控制 · COM3 ●] [变频器 · COM5 ●] [本地从机 · TCP] [更多 ▼] [+]
──────────────────────────────────────────────────────────────────────────────
当前连接状态 / 连接配置
设备列表：Unit 1、Unit 2……
当前设备点表、实时值、写入
当前连接请求/响应报文
```

### 10.2 「全部连接」职责

只展示连接管理表或卡片：

- 名称、角色、RTU/TCP、COM/端点。
- 启用和连接状态。
- 设备数、点位数。
- 最近成功、连续失败、报警数量。
- Agent 正在运行的任务和待确认数量。
- 创建、编辑、启停、删除。

禁止在「全部连接」下面展开所有设备、点位、曲线和报文。

### 10.3 具体连接标签职责

切换标签后，以下内容共同切换：

- 当前连接状态与配置。
- 该连接下设备/Unit ID。
- 当前设备点位与实时值。
- 该连接轮询状态。
- 该连接趋势和报警入口。
- 该连接写入面板。
- 该连接报文和通信统计。
- 该连接上的 Agent 任务和证据。

### 10.4 标签显示规则

- RTU：`连接名称 · COM3`。
- TCP 客户端：`连接名称 · 192.168.1.20:502`。
- TCP 服务端：`连接名称 · Listen :502`。
- 状态使用图标和文字辅助，不只依赖颜色。
- 标签显示异常数、Agent 任务、待确认角标。
- 超过可用宽度后使用横向滚动和「更多连接」菜单，不无限压缩文字。
- 支持键盘左右切换、Home/End 和清晰焦点样式。

连接稳定身份始终是 `connectionId`。COM 拔出、重新枚举或连接改名都不能使证据和任务丢失关联。

### 10.5 设备选择

- 当前连接下使用设备列表/树展示名称、Unit ID、启用、状态和点位数。
- 保留每条连接最后选择的设备，切换回来时恢复；这是界面偏好，不改变连接数据模型。
- 相同连接下 Unit ID 必须唯一；不同连接可以使用相同 Unit ID 和地址。

### 10.6 Agent 在非当前连接上的行为

- 后台读取和轮询只更新标签角标，不强制抢走用户焦点。
- Agent 明确调用 `focus` 时才切换连接和设备，并提供返回原焦点。
- 高影响确认无论在哪个连接产生，都显示全局待办；打开后进入正确连接标签。
- 确认卡显示连接名称、COM/端点、设备、Unit ID、点位、地址和配置版本。

## 11. 侧边栏重构

### 11.1 统一侧栏上下文

「监视、曲线、告警」默认跟随上位机当前连接和设备，同时支持“固定当前范围”。

侧栏顶部统一显示：

- 当前工作区。
- 当前连接及端点。
- 当前设备及 Unit ID。
- `跟随上位机 / 已固定` 状态。
- “在上位机打开”。

侧栏不自行维护另一套连接或点位配置。

### 11.2 「点表」改为「监视」

保留：

- 当前监视组中的点位和实时值。
- 原始值、工程值、单位、质量和采集时间。
- 暂停/恢复和刷新周期。
- 点位搜索和固定。
- 跳转上位机和“让 Agent 分析”。

移出侧栏：

- 新增/删除点位。
- 地址、类型、字节序和报警规则配置。
- CSV/JSON 导入导出。
- 批量编辑。

初期取消侧栏直接写入，改为打开上位机完整写入面板。显式对象 ID、目标提示和确认流程完成后，再恢复受控快捷写入。

### 11.3 「曲线」

侧栏曲线负责短窗口快速观察：

- 只显示当前监视组或用户选择的序列。
- 每条序列绑定 `connectionId + deviceId + pointId`。
- 质量不为 `good` 时写入缺失点并断线，不跨超时/断线连接曲线。
- 显示当前值、最小、最大、平均和变化速率。
- 支持暂停、缩放、平移和恢复实时。
- 支持选择时间区间并发送给 Agent。
- 支持“在上位机完整曲线中打开”。

优先验证 uPlot：使用 `null`/缺失数据表达质量断点，以插件主题适配其样式。原型必须验证 Windows 缩放、DPI、暗色主题、8 条序列和持续更新 CPU 占用。

### 11.4 「告警」

侧栏告警从事件列表升级为状态视图：

- `当前` 与 `历史` 两个视图。
- 激活、恢复、已确认状态。
- 严重度、首次发生、最后发生、重复次数和持续时间。
- 连接、设备、Unit ID、点位、当前值、阈值和质量。
- 通信故障与过程报警分组。
- 死区、延时和去重结果。
- 确认来源为用户或 Agent 建议，最终确认仍由用户触发。
- 跳转点位、曲线区间和来源报文。
- “让 Agent 分析”发送结构化异常引用和前后数据查询参数。

## 12. 「串口报文」侧栏

### 12.1 页面入口

侧栏新增：

```text
监视 | 曲线 | 告警 | 串口报文 | 工程
```

调试页不再保留完整串口日志面板，只保留打开「串口报文」的入口和与当前调试任务有关的严重提示。

### 12.2 COM 选择

顶部提供：

- `全部串口`。
- 每个已配置 RTU 连接的 COM。
- 已插入但尚未建立连接的 COM，仅在“原始数据”模式中可选。

选项显示：

```text
COM3 · 冷机控制 · 已连接
COM5 · 变频器 · Agent读取中
COM7 · CRC错误 3
```

内部选择值优先使用 `connectionId`；对于未配置的原始串口使用规范化 COM 标识。不能仅靠显示字符串关联历史证据。

### 12.3 两种数据模式

#### 协议报文

- 数据来自插件自身 PyModbus 请求/响应和服务端处理过程。
- 即使 COM 正被该连接占用，也能查看，因为不需要第二次打开端口。
- 只声称展示本插件实际发送和接收的数据，不声称监听整条物理总线。
- 支持请求/响应配对、原始 Hex、解码、方向、Unit ID、功能码、耗时、异常码、CRC/超时结果和来源任务。

#### 原始数据

- 复用当前 PySerial 串口监视能力。
- 支持文本、Hex 和自动换行展示。
- 用于设备 UART 输出、未知协议和接线/波特率诊断。
- Windows 下如果 COM 已被 Modbus 或其他程序占用，明确返回 `PORT_IN_USE`，不尝试旁路打开。
- 若确实需要物理总线旁听，产品只提示使用独立只听适配器；不把它伪装成软件能力。

### 12.4 报文行内容

每条至少显示：

- 时间和 `frameId/transactionId`。
- COM、连接名称和方向 `TX/RX`。
- 设备/Unit ID。
- 功能码和数据区。
- 原始 Hex。
- 解码摘要。
- 响应耗时、超时、CRC或协议异常。
- 来源：用户、Agent、轮询、服务端或系统。

操作包括：暂停滚动、过滤、搜索、复制 Hex、复制事务、导出当前范围、在上位机打开、让 Agent 分析。

### 12.5 列表性能与缓存

- 继续使用连接级环形缓存，协议报文与原始数据分源保存。
- 「全部串口」只是按时间合并投影，不复制底层帧。
- 初期维持每连接 500 条协议帧上限；原始文本维持现有 2000 行上限，后续根据内存实测调整。
- 使用虚拟列表展示大量记录，避免每次轮询重绘全部 DOM。
- “清空显示”默认只清除当前视图过滤或游标；真正删除缓存必须有明确动作，避免证据意外丢失。

## 13. Agent 与页面双向联动

### 13.1 Agent 操作回显

Agent 发起以下操作时，上位机或调试页必须显示目标、来源、进度和结果：

- 编译、读取、轮询验证。
- 连接状态查询。
- 报文和异常分析。
- 监视组和快照创建。
- 配置草稿。
- 写点、下载和复位请求。

页面状态来自共享任务和时间线，不通过解析聊天文字猜测 Agent 做了什么。

### 13.2 界面发送给 Agent

以下对象提供“让 Agent 分析”：

- 连接和设备。
- 点位或监视组。
- 协议事务或原始数据区间。
- 曲线时间区间。
- 告警和通信故障。
- 编译错误、产物和下载结果。

发送内容是结构化引用，至少包含稳定 ID、配置版本、时间范围和复查参数；不只复制屏幕文本。

### 13.3 Agent 驱动界面

Agent 可以请求：

- 打开调试或上位机页面。
- 选择连接标签和设备。
- 高亮点位、报文、告警或曲线区间。
- 打开相应侧栏。
- 创建临时监视组和诊断标记。

普通后台事件不得强制改变焦点。所有自动聚焦提供可见提示和返回入口。

### 13.4 配置草稿

- 草稿以 RFC 6902 patch 表示，基于明确的 `baseConfigVersion`。
- 界面展示新增、删除、修改、COM冲突、Unit ID冲突和影响点位数。
- 用户批准前不写入共享配置。
- 批准时重新校验基线版本、端点指纹和对象存在性。
- 发生漂移后返回 `CONFIG_DRIFT`，要求 Agent 重新生成草稿。

## 14. 分阶段执行顺序

### N0：契约冻结与基线同步（P0）

目标：不在主计划仍修改同一文件时制造冲突。

- 等待当前 R1 改造形成干净提交。

门槛：评审不再对核心对象身份、页面职责和权限分类存在歧义。

### N1：Corn模式与导航清理（P0）

- 更名为「Corn模式」，保留 `corn-bench` ID。

- 「点表」改为「监视」。

### N3：趋势与告警补强（P1，对齐主计划 R2）

- uPlot 原型通过后替换手写基础曲线。

- 告警激活/恢复/确认状态、通信与过程分组、去重。

门槛：断线区间不被画成连续正常曲线；告警可追溯到点位、质量和来源报文。

### N4：Agent 深度联动（P1，对齐主计划 R3）

- 工具显式对象 ID 全量收口。
- UI focus、高亮、临时监视组和证据跳转。
- RFC 6902 配置草稿和差异确认。
- 报文、趋势、告警一键发送给 Agent。
- Agent 结论回挂现场证据。

门槛：Agent 每个现场操作都能在界面看到；每个结论都能跳回相同证据。

### N5：Windows 发布验收（P0 发布门槛）

- Windows 10/11 全新安装、旧预设升级和重启恢复。
- COM1–9、COM10+、USB 拔插、第三方占用、双 COM 并行。
- DPI、暗色主题、连接标签溢出、虚拟列表和曲线性能。
- 真实设备 Agent 读写、拒绝、批准、漂移和回读完整流程。

门槛：所有自动化与 Windows 手工场景通过，未执行项在发布记录中明确列出。

## 16. 自动化验收场景

### 16.1 预设

1. 全新安装只创建一个 `corn-bench`，显示名为「Corn模式」。
2. 已安装旧「台架模式」原地更名，不创建第二个目录。
3. 已知旧 persona 能迁移到新提示区段，旧规则不重复出现。
4. 用户修改过的未知 persona 不被覆盖，并返回可读诊断。
5. 重复启动不重复插入插件行。
6. 外部占用 `corn-bench` ID 且无 ownership 标记时拒绝修改。
7. Corn提示区段和工具只对选择该预设的 Agent 可见。
8. 旧 Session 保持原组合，新 Session 使用更新后的预设。

### 16.2 上位机连接标签

9. 1、2、6、16 个连接下标签、溢出和更多菜单正常。
10. 切换连接只展示该连接设备、点位、轮询和报文。
11. 同地址点位分属两条连接时不串值、不串写、不串告警。
12. 每条连接恢复上次选中的设备。
13. Agent 在非当前连接读取时只显示角标，不抢焦点。
14. Agent 请求聚焦后切到正确连接、设备和证据。
15. 非当前连接待确认能从全局提示跳到正确确认卡。

### 16.3 侧边栏

16. 「监视」只显示当前或固定范围，不展示其他设备同地址点位。
17. 侧栏点位能跳回上位机完整页面。
18. `stale/timeout/disconnected` 值不显示为正常绿色。
19. 曲线在坏质量区间断线，恢复后不跨空档连线。
20. 曲线选择区间生成稳定证据引用。
21. 告警区分激活、恢复、确认以及通信故障/过程报警。

### 16.4 串口报文

22. `全部串口` 能按时间合并 COM3 与 COM5，单 COM 过滤准确。
23. 协议报文显示请求/响应、Unit ID、功能码、Hex、耗时和来源。
24. Agent 发起读取后，报文来源标记 Agent 并关联同一 taskId。
25. COM 正被本插件 Modbus 占用时仍能看协议报文。
26. 同一 COM 启动原始监听时返回 `PORT_IN_USE`。
27. COM10+ 正确枚举、选择和打开。
28. USB拔出后保留历史并标为断开，重新插入后连接身份不变。
29. 大量报文滚动时 DOM 数量受控，暂停后不丢底层缓存。

### 16.5 Agent 安全

30. Agent 不提供目标 ID 时，现场读写返回 `TARGET_REQUIRED`。
31. 写点确认绑定连接、设备、点位、配置版本和端点指纹。
32. 确认前切换 COM 或 Unit ID 后旧请求失效。
33. 用户拒绝后不产生设备写入。
34. 写入批准后显示协议结果和回读一致性。
35. 配置草稿发生版本漂移时不能应用。

## 17. Windows 手工验收场景

- 两个 USB-RS485 分别配置 COM3 与 COM5，同时轮询。
- 单个 RS485 总线挂两个 Unit ID，配置相同寄存器地址。
- 第三方串口工具占用 COM，插件显示占用而不影响另一 COM。
- 在 Agent 会话中让 Agent 读取 COM5，同时用户停留在 COM3。
- 从连接角标进入 Agent 任务和对应协议事务。
- 在串口报文侧栏选择全部、COM3、COM5并检查过滤。
- 切换协议报文和原始数据，验证独占行为。
- 产生一次超时和一次 CRC/协议异常，检查报文、质量、曲线和告警关联。
- 选择曲线异常区间发送给 Agent，再从 Agent 结论跳回相同区间。
- Agent 请求写点，分别验证拒绝、批准、端点漂移和回读不一致。
- 关闭并重启 DSH，检查 Corn模式、连接标签、侧栏固定范围和历史证据恢复。

| 高影响追溯 | 100% 有来源、目标、请求哈希、结果和证据 |
| 预设升级 | 已知旧版本自动迁移成功；未知用户修改 0 覆盖 |
| 无 Agent 可用性 | 用户不使用 Agent 仍能完成完整上位机流程 |

性能数字先作为验收下限，不虚构用户效率提升比例。R1/R2 实装后再记录真实 Windows CPU、内存、绘制帧率和操作耗时基线。

## 19. 明确不做

本计划不增加：

- CAN/DBC。
- 远程 Runner。
- 多人共享台架和预约。
- 设备市场、模板市场和行业知识包。
- 云端历史数据库。
- 图形化 HMI/组态画面编辑器。
- 企业级报警路由、排班和值班通知。
- 物理总线无侵入嗅探器。
- Agent 静默写点、下载或复位。
- 为连接标签自建通用 UI 框架。
- 为趋势、虚拟列表、YAML 和 JSON Patch 重写已有成熟基础库。

## 20. 风险与处理

| 风险 | 影响 | 处理 |
|---|---|---|
| 主计划仍修改 `bench-hmi/bench-store` | 产生冲突和重复返工 | N0 等待干净基线，再按模块顺序实施 |
| 用户预设是 standard 快照 | 官方更新不能自动继承 | Corn规则移到插件提示区段；基础更新只提示和安全重建 |
| YAML 自动写回影响用户格式 | 用户不信任升级 | 使用 Document API、备份、ownership 限定和幂等测试 |
| 侧栏与上位机各自保存状态 | 产生两个真相 | 同一 store、同一对象 ID；侧栏只保存范围偏好 |
| 报文被误认为总线嗅探 | 诊断结论错误 | 明确标注“本插件 TX/RX”；原始监听遵守 COM 独占 |
| 图表库与插件主题冲突 | Windows暗色/DPI异常 | 先做独立原型和 bundle 检查，再进入正式实现 |
| Agent 自动聚焦打断用户 | 交互混乱 | 后台任务只角标；显式 focus 才切换并可返回 |
| 多连接 schema 继续兼容隐式当前对象 | 误操作风险 | P0 收口显式 ID，兼容只保留迁移读取，不用于现场写入 |

## 21. 完成定义

只有同时满足以下条件，本计划才能标记完成：

- 用户只看到「Corn模式」，旧安装可安全迁移且用户修改不丢失。
- Corn规则随插件更新，不再依赖替换复制预设中的整句 persona。
- 「总览」Tab 已删除，原有关键能力没有丢失。
- 上位机按连接标签切分内容，多个连接不再纵向堆叠。
- 侧栏为「监视、曲线、告警、串口报文、工程」，职责不与上位机配置重复。
- 串口报文支持全部或指定 COM，正确区分协议报文和原始数据。
- Agent 对连接、设备、点位和报文的操作在界面中可见，不静默改变现场。
- 所有高影响操作保持人工确认、端点漂移保护和可追溯证据。
- 自动化测试、生成客户端检查、Windows 真实多 COM 和 Agent 人工验收全部通过。
