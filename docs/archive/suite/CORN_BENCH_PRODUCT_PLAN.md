## 1. 文档目的

本文档定义 `dsh-corn-bench` 后续一段时间内的产品定位、功能范围、交互模型、Session Agent 联动方式、阶段目标和验收标准。

规划只面向以下产品形态：

- 在一台 Windows 电脑上部署 DeepSeek Harness 和本插件。
- 连接一套本地嵌入式或工业控制台架。
- 用户既可以使用传统调试界面和上位机界面，也可以让当前 Session 的「台架模式」Agent 参与工作。
- Keil、OpenOCD、Python、串口和 Modbus 等能力均由本机直接提供。

本文档不规划远程 Runner、多人共享、设备市场或跨行业平台化能力。

---

## 2. 产品定位

`dsh-corn-bench` 不是一个单纯的编译按钮集合，也不是一个只靠对话操作设备的 AI 工具。

它的定位是：

> 面向嵌入式与工业控制开发的本地 AI 台架工作站，让传统调试、上位机监控和当前 Session Agent 围绕同一份现场状态协同工作。

插件需要同时满足两种使用方式：

1. **不使用 Agent 时**，它是一套完整、直观、可靠的传统调试界面和上位机界面。
2. **使用台架模式 Agent 时**，Agent 能理解当前工程、设备、连接、日志、测点和最近操作，并能参与编译、诊断、验证和测试流程。

Agent 是台架的协作者，而不是传统界面的替代品。

## 3. 产品目标

### 3.1 核心目标

- 统一管理当前工作区、Keil 工程、Target、固件产物和本机工具绑定。
- 提供传统的编译、下载、日志查看、Modbus 监控和数据趋势能力。
- 建立调试界面、上位机界面与当前 Session Agent 的双向联动。
- 让 Agent 基于真实现场状态和证据工作，而不是猜测工程、设备和结果。
- 形成“修改代码 → 编译 → 下载 → 运行 → 观察 → 判断”的本地闭环。
- 对所有重要操作保留来源、时间、输入、结果和关联 Session。

### 3.2 成功标准

当插件达到可正式使用状态时，用户应能完成以下工作：

1. 在 Windows 上绑定并检查 Keil、Python、OpenOCD 等本机程序。
2. 打开一个工程工作区，选择 Keil 工程和 Target。
3. 在传统界面中完成编译、查看错误、选择产物和下载固件。
4. 按“连接 → 设备/Unit ID → 点位”的层级配置一条或多条本机通信线。
5. 同时运行多条不冲突的 RTU/TCP 连接，并按连接查看实时值、质量、报文和通信诊断。
6. 在上位机界面中查看点表、实时数值、趋势曲线和本地报警。
7. 将错误、日志、连接、设备、点位、报文或曲线区间发送给当前 Session Agent。
8. 由 Agent 发起编译、读取、诊断或验证，并在界面中看到全过程。
9. 对写点、下载、复位等高影响操作进行人工确认，并对写入进行结果回读。
10. 回看一次问题从发现、分析到验证完成的完整证据链。

### 3.3 阶段性产品指标

| 指标 | 当前基线 | R1 目标 | 证据 |
|---|---:|---:|---|
| 同一工作区可运行连接数 | 1 | 至少 2 条不同 COM 并行 | Windows 手工验收 + 并发测试 |
| 同一连接可配置 Unit ID 数 | 1 | 至少 2，且同地址点位不串扰 | 多 Unit ID 集成测试 |
| 错目标写入 | 未覆盖多连接 | 0 | 审批、端点漂移与回读用例 |
| 连接故障隔离 | 单连接无参照 | 一条失败不影响其他连接 | 故障注入测试 |
| 高影响操作可追溯率 | 已有基础时间线 | 100% 带来源、目标、结果和证据 | 时间线契约测试 |
| Agent 现场对象定向率 | 主要依赖当前单连接 | 100% 使用稳定对象 ID | Tool schema 与联动验收 |

R1 上线后再采集“从新建工程到首次读到有效点值”的耗时基线；在没有真实用户数据前，不虚构激活率或效率提升百分比。

## 4. 明确不做的内容

当前规划明确排除以下方向：

- macOS 正式部署支持。
- 远程 Windows Runner 或跨机器执行。
- 跨电脑、跨台架或远程 Runner 的设备拓扑管理。
- 多人共享台架、预约和权限租约。
- CAN/DBC。
- 设备模板市场或公共配置市场。
- 暖通、空调、储能等独立行业知识包。
- 云端台架管理。
- 团队级测试管理平台。
- 用聊天界面完全取代传统调试界面和上位机界面。

这些内容在当前阶段不预留复杂架构，不作为验收条件，也不影响本地单机版本发布。

> **边界说明（2026-08-22）**：一条本机 Modbus RTU 通信线下配置多个 Unit ID，是串行总线的基础能力，不属于平台化“多设备拓扑”。本地多 COM、多 TCP 连接、本地从机仿真和同一通信线下多 Unit ID 均在本规划内；远程节点编排、跨台架关系图、集中资产管理仍不在规划内。

## 5. 核心设计原则

### 5.1 一份现场，多种入口

调试界面、上位机界面和 Agent 必须读取同一份台架状态，不允许各自维护互相冲突的工程、设备和连接信息。

### 5.2 传统操作始终可用

所有核心功能都必须可以由用户直接在界面中完成。Agent 失效、模型不可用或用户不想使用 Agent 时，插件仍然可以正常完成日常调试工作。

### 5.3 Agent 双向联动

联动包括四个方向：

- 界面状态可以被 Agent 查询。
- 重要现场变化可以主动通知当前 Session Agent。
- 用户可以把选中的界面内容发送给 Agent。
- Agent 的操作、进度和结论可以回到界面中展示。

### 5.4 不把实时数据全部塞进提示词

Agent 的现场认知分为三层：

1. 预设提供稳定、简短的台架工作规则。
2. 重要变化以结构化事件通知当前 Session。
3. 大体量日志、曲线和测点数据由 Agent 按需调用工具查询。

### 5.5 人在回路

读取、查询和诊断可以自动执行；写点、下载固件、复位设备等操作必须让用户清楚地看到目标和影响，并在需要时确认。

### 5.6 所有结论都能追溯证据

Agent 的诊断应关联到具体编译记录、日志区间、测点快照、曲线区间或操作结果，不能只保留一段脱离现场的文字结论。

### 5.7 连接、设备和点位不能混为一层

目标模型固定为：

```text
Workspace
├── Connection（物理或网络通信线）
│   ├── Device（该通信线下的 Unit ID / 本地服务端映射）
│   │   └── Point（线圈、离散输入、保持寄存器、输入寄存器）
│   └── Frames / Health / Polling（连接级运行状态）
├── Timeline / Tasks / Evidence
└── Session Binding / Agent Focus
```

约束如下：

- `Connection` 负责传输方式、端点、角色、生命周期和资源占用。
- `Device` 负责 Unit ID、设备名称、启停状态和设备级轮询策略。
- `Point` 必须同时引用 `connectionId` 和 `deviceId`，不能只引用 COM 或连接。
- 点位 `id` 使用独立、全局唯一的持久化 ID；`connectionId + deviceId + area + address + bitOffset` 是业务定位键，不再用 `p${function}_${address}` 充当跨设备唯一 ID。
- 界面当前焦点分别记录为 `activeConnectionId`、`activeDeviceId` 和可选 `activePointId`。
- 所有 Agent 工具、任务、时间线和证据引用都使用同一组对象 ID。

### 5.8 协议语义与界面语言分开

- 产品界面可以继续显示用户熟悉的“主机/从机”，同时标注“客户端/服务端”。
- 内部模型统一使用 `client/server`，避免把“上位机创建一个从机连接”和“上位机连接远端从机设备”混淆。
- 点位类型使用 `area: coil | discreteInput | holdingRegister | inputRegister` 表达。
- `FC01/02/03/04` 是读取功能；写线圈使用 `FC05/15`，写保持寄存器使用 `FC06/16`。计划、界面和日志必须分别展示“数据区”和“实际读写功能码”。

## 6. 整体功能结构

插件最终由五个用户可感知的功能区域组成。

### 6.1 台架总览

台架总览是用户和 Agent 理解当前现场的统一入口。

展示内容包括：

- 当前工作区。
- 当前 Keil 工程与 Target。
- 当前 Git 分支和工作区变更提示。
- Python、Keil UV4、OpenOCD 可用状态。
- 当前调试器和设备连接状态。
- 最近一次编译结果。
- 当前选择的固件产物及其生成时间。
- Modbus 连接、设备和轮询状态（`connections/devices/activeConnectionId/activeDeviceId/pollingByConnection`）。
- 串口连接状态。
- 当前 Session 与台架模式 Agent 的绑定状态。
- 最近重要事件和待确认操作。

总览提供以下快捷入口：

- 打开调试页。
- 打开上位机页。
- 查看最近失败。
- 发送当前台架快照给 Agent。
- 让 Agent 检查当前现场。
- 处理 Agent 发出的人工操作请求。

### 6.2 调试界面

调试界面负责工程、编译、固件和设备下载流程。

主要区域：

- 工程与 Target。
- 编译控制与结果。
- 错误和警告列表。
- 固件产物。
- 下载与验证。
- 串口日志。
- 调试操作记录。

### 6.3 上位机界面（下一阶段：连接—设备—点位）

上位机界面负责本机多 Modbus 通信线的创建、设备配置、点位监控、报文诊断、趋势查看和受控写入。标准操作路径为：

```text
创建工程
→ 新建客户端/主机或服务端/从机连接
→ 配置并检查 COM 或 TCP 端点
→ 在连接下添加设备 / Unit ID
→ 在设备下添加点位
→ 连接并轮询或监听
→ 按连接查看报文，按设备查看点值和异常
```

主要区域：

- **连接列表**：展示连接名称、客户端/服务端角色、RTU/TCP、端点、启用状态、连接状态、最后成功时间和连续失败次数。
- **设备树**：选中连接后列出该通信线下的设备。客户端连接可包含多个 Unit ID；服务端连接展示本地暴露的一个或多个 Unit ID 地址空间。
- **连接配置**：RTU 配置 COM、波特率、数据位、校验位、停止位、超时、重试和重连；TCP 客户端配置远端 `host:port`，TCP 服务端配置本地监听地址。
- **点表与分组**：只展示当前设备的点位；全局搜索时仍显示所属连接、设备和 Unit ID，避免同地址点位混淆。
- **实时数据表格**：显示工程值、原始值、质量、采集时间、最后成功时间、错误和来源报文；轮询可以按连接和设备暂停。
- **趋势与本地报警**：按连接/设备选择点位，异常事件保留 `connectionId/deviceId/pointId`。
- **写入与回读**：根据点位数据区自动选择 FC05/06，后续批量写入使用 FC15/16；界面展示写前值、目标值、协议写入结果和回读值。
- **连接级报文分析器**：底部使用 `全部 | 连接名称...` 切轨，不用 COM 名作为唯一标签，以兼容 TCP；选中报文可查看原始十六进制、解析字段、请求/响应配对、耗时和异常。
- **Agent 入口**：连接、设备、点位、报文、趋势区间和异常均提供“让 Agent 分析”，发送稳定对象引用而非屏幕文本。

### 6.4 台架时间线

时间线统一记录用户、Agent、设备和系统产生的重要事件。

主要用途：

- 回看一次问题处理过程。
- 在界面记录和 Session 对话之间互相跳转。
- 识别某个操作由谁发起。
- 为 Agent 诊断提供最近事件。
- 为测试报告提供可追溯证据。

### 6.5 Session Agent 联动层

联动层不单独替代业务页面，而是贯穿总览、调试、上位机和时间线。

它负责：

- 当前 Session 绑定。
- 预设 Agent 能力装配。
- 工具查询和操作。
- 重要事件通知。
- 界面选区发送。
- Agent 操作回显。
- 用户确认和人工步骤。
- Agent 结论挂接到现场证据。

## 7. 台架状态与 Session 状态

为了实现正确联动，需要明确区分三类状态。

### 7.1 台架共享状态

台架共享状态代表当前电脑和真实设备的客观情况：

- 当前工作区。
- 当前工程和 Target。
- 本机工具绑定。
- 当前 Modbus 配置版本与迁移结果。
- `connections[]`：通信线、角色、端点、启停和生命周期状态。
- `devices[]`：所属连接、Unit ID、名称、启停和设备级轮询配置。
- `points[]`：所属连接和设备、数据区、地址、类型、换算、访问属性和报警配置。
- `values[]`：点位当前原始值/工程值、质量、时间戳、错误和来源报文。
- `pollingByConnection` 与设备级轮询状态。
- `framesByConnection` 与连接统计。
- 本机端点资源占用：RTU COM 和 TCP 服务端监听地址。
- 最新固件产物。
- 最近编译、下载和设备操作。

它由传统界面和 Agent 共同读取。

### 7.2 当前 Session 关注状态

Session 状态代表当前 Agent 正在处理的任务：

- 当前诊断目标。
- Agent 正在关注的错误、日志或点位。
- 用户发送给 Agent 的曲线区间。
- 当前执行中的验证流程。
- 等待用户完成的人工操作。
- Agent 给出的阶段性结论。

Session 关注状态只保存“正在看什么”，不复制点值、连接状态或报文正文。实时对象仍从共享台架状态按 ID 查询。

同一个台架状态可以被不同 Session 观察，但只有当前绑定的 Session 接收主动通知和交互请求。

### 7.3 操作任务状态

编译、下载、采样和测试不能只表现为一次按钮点击，需要形成可追踪任务：

- `taskId`。
- 任务类型。
- 发起来源：用户或 Agent。
- 关联 Session。
- 开始时间和结束时间。
- 当前阶段和进度。
- 输入参数。
- 标准输出、错误输出和附件。
- 最终结果。
- 是否等待用户确认。
- 是否被取消或超时。

涉及 Modbus 的任务还必须包含：

- `connectionId`。
- 可选 `deviceId`、`pointId`、`frameId`。
- 实际端点指纹和 Unit ID。
- 请求功能码、写入功能码或监听角色。
- 请求/响应报文引用。

## 8. 传统调试功能规划

### 8.1 工程管理

- 浏览工作区内的 Keil 工程。
- 显示工程名称、路径和最近使用时间。
- 解析并列出 Target。
- 记住每个工作区最后使用的工程和 Target。
- 显示当前 Git 分支和是否存在未提交改动。
- 显示工程使用的 MCU、输出目录和主要构建信息。
- 提供“发送工程信息给 Agent”。

### 8.2 编译

- 支持选择 Target 和构建配置。
- 显示编译进行状态和耗时。
- 结构化解析 errors、warnings、ROM 和 RAM 占用。
- 错误列表支持文件、行号、错误码和消息。
- 支持复制错误、批量选择和发送给 Agent。
- 保存最近若干次编译记录。
- 对比前后两次固件体积。
- 显示编译日志并支持搜索、过滤和导出。
- Agent 发起的编译在界面中明确标记来源。

### 8.3 固件产物

- 识别 HEX、BIN、AXF、ELF 等产物。
- 显示文件路径、大小、生成时间和哈希。
- 标记当前待下载产物。
- 保留最近使用产物记录。
- 编译完成后提示所需格式是否生成。
- 支持将产物信息发送给 Agent。

### 8.4 下载与验证

- 支持通过 Keil 或 OpenOCD 下载固件。
- 下载前展示工程、Target、产物、设备和风险说明。
- 下载前要求用户确认高影响操作。
- 显示下载进度和日志。
- 下载后执行校验。
- 可选执行复位和运行。
- 读取设备固件版本或用户定义的验证点。
- 将“产物版本”和“设备实际版本”进行对比。
- 失败时保留完整上下文供 Agent 分析。

### 8.5 串口日志

- 串口选择、波特率和常用参数配置。
- 连接、断开和自动重连。
- 实时时间戳。
- 暂停显示但不停止采集。
- 关键字过滤和搜索。
- 错误、警告、重启、断言等日志高亮。
- 选中一段日志发送给 Agent。
- Agent 查询最近若干行或指定时间范围日志。
- 日志导出和关联编译、下载记录。

## 9. 传统上位机功能规划

### 9.1 Modbus 工程模型（下一阶段）

工作区目标结构为：

```text
modbus: {
  version: 3,
  connections: Connection[],
  devices: Device[],
  points: Point[],
  values: QualifiedValue[],
  activeConnectionId,
  activeDeviceId,
  pollingByConnection,
  framesByConnection,
  alarmState
}
```

`Connection`、`Device` 和 `Point` 使用扁平集合与外键关联，便于统一查询、CSV/JSON 导入和 Agent 工具输出；不在持久化层同时维护嵌套副本。

#### 9.1.1 连接与角色

- 支持多条 RTU/TCP 连接，内部角色使用 `client/server`，界面显示“客户端/主机”“服务端/从机”。
- 客户端连接主动轮询和写入；服务端连接监听请求并维护本地地址空间。
- 每条连接独立保存端点、超时、重试、自动重连、启用状态和健康统计。
- 支持新增、重命名、复制、启停、连接、断开和删除。
- 删除连接时必须列出将同时删除的设备、点位和未导出的历史数据，并二次确认。
- `activeConnectionId` 只代表界面焦点，不代表唯一运行连接。

#### 9.1.2 端点唯一性与资源锁

- 两条已启用 RTU 连接不可配置同一个 COM；下拉列表显示占用连接名称。
- 保存时进行工程级冲突校验，打开时仍必须通过运行时端点租约；被其他软件占用时显示系统错误与排查建议。
- TCP 服务端的本地 `listenHost:listenPort` 必须唯一，因为它是监听资源。
- TCP 客户端连接同一远端 `host:port` 在协议上不属于端口占用冲突。产品应优先提示用户在同一连接下增加多个 Unit ID，而不是错误地按操作系统资源冲突处理；确有需要时允许多个客户端会话。
- 仿真只占用它实际打开的资源：内存仿真不占 COM；RTU 服务端仿真打开 COM 后占用 COM；TCP 服务端仿真监听端口后占用本地监听地址。
- 缺少端点或端点冲突只阻断相关连接，不影响其他连接继续运行。

#### 9.1.3 设备 / Unit ID 层

- `Device{id, connectionId, name, unitId, enabled, pollingProfileId, notes}`。
- 客户端 RTU 连接允许多个 Unit ID；同一连接内 Unit ID 必须唯一。
- TCP 客户端也保留 Unit ID，用于网关或桥接设备后的目标寻址。
- 服务端连接使用同一设备模型表示本地暴露的 Unit ID 地址空间。
- 设备可以独立暂停轮询，但不能绕过连接生命周期。
- 删除设备时只影响该设备的点位、值和告警，不影响同一连接下其他设备。

#### 9.1.4 点位身份与归属

- `Point{id, connectionId, deviceId, name, area, address, bitOffset, length, dataType, byteOrder, wordOrder, scale, offset, unit, access, scanGroup, alarm...}`。
- `id` 是独立生成的稳定 ID；不得继续使用 `p${function}_${address}` 作为跨设备唯一键。
- 同一连接的不同 Unit ID 可以拥有相同数据区和地址，不得互相覆盖。
- `QualifiedValue` 以 `pointId` 为主键，并冗余 `connectionId/deviceId` 便于过滤和证据导出。
- 所有点位增删改查、读写、趋势、报警和 Agent 工具都必须携带稳定对象 ID。

#### 9.1.5 报文分轨与事务关联

- 每连接保留独立环形缓冲；“全部”视图由查询时聚合，不持久化第二份可产生不一致的数据。
- 切轨标签使用连接名称和端点摘要，例如 `主控板 · COM3`、`网关 · 192.168.1.10:502`。
- 每条记录至少包含 `frameId/connectionId/deviceId?/unitId/direction/timestamp/rawHex/functionCode/address/quantity/status/exceptionCode/crcOk/latencyMs/taskId/sessionId`。
- 请求与响应通过 `transactionId` 或内部 `requestId` 配对；点值保存来源 `requestFrameId/responseFrameId`。
- 支持按连接、方向、Unit ID、功能码、状态和时间范围过滤，支持暂停显示、复制和导出。
- `pollLocks` 按连接控制轮询状态；物理端点锁按 COM 或本地监听地址控制资源，两个不同 COM 可以并行。

#### 9.1.6 v2 → v3 迁移

- 旧 `conn` 迁为一个客户端连接 `c1`。
- 旧 `conn.slave` 迁为该连接下的设备 `d1`。
- 旧 `points` 为每项生成新的稳定 ID，并同时写入 `connectionId:c1`、`deviceId:d1` 和对应 `area`。
- 旧 `values` 通过迁移映射表关联到新 `pointId`；无法映射的数据进入迁移报告，不静默丢弃。
- 旧单轨报文只迁入 `c1`；迁移完成后保存备份和迁移版本，重复加载不得再次生成新 ID。
- 迁移失败时保持旧文件可恢复，不覆盖原始工作区。

### 9.2 点表

- 手工创建点位时先选择连接和设备；在设备页面创建时自动继承所属 ID。
- CSV/JSON 导入支持“导入到当前设备”和“按外部键映射全量导入”两种模式，导入前提供校验预览，不直接覆盖。
- 点位至少包含名称、分组、数据区、地址、位偏移、寄存器长度、数据类型、字节序、字序、倍率、偏移、单位、访问属性、枚举、扫描组、报警配置和备注。
- 数据区与访问规则：`discreteInput/inputRegister` 只读；`coil/holdingRegister` 可以配置为只读或可写。
- 读取分别使用 FC01/02/03/04；单点写入使用 FC05/06；批量写入属于后续能力，使用 FC15/16。
- 支持 UINT16、INT16、UINT32、INT32、FLOAT32、BOOL、HEX 和位域；字符串、64 位类型在有真实需求后进入后续版本。
- 32 位点位明确选择 ABCD/CDAB/BADC/DCBA 等字节/字序组合，并在导入校验中检测寄存器长度。
- 点位列表和全局搜索始终显示连接、设备与 Unit ID，防止同地址误操作。
- 删除点位后保留时间线与历史证据中的只读快照，不让旧证据失去解释上下文。

### 9.3 实时监控与质量

- 轮询计划按连接串行调度，按设备和连续地址合并请求；不同物理连接可并行。
- 支持连接级、设备级暂停和恢复；暂停只停止新请求，不抹除最后值。
- `QualifiedValue` 至少包含原始值、工程值、质量、采集时间、最后成功时间、错误、连续失败次数和来源报文。
- 质量枚举至少区分 `good/stale/timeout/disconnected/protocolError/configError/unknown`。
- 断线或超时后保留最后值但明确标记为非实时，禁止继续用绿色正常状态展示。
- 支持轮询组与刷新周期，R1 最低限制为每设备 200ms，实际下限由连接吞吐和点数校验决定。
- 支持按设备创建状态快照；快照记录连接端点指纹、Unit ID、点位配置版本和时间。
- Agent 可按连接、设备、分组或点位 ID 查询，不允许省略目标后默认写入“当前连接”。

### 9.4 趋势曲线

- 多点位同图显示。
- 时间范围缩放和拖动。
- 显示最大值、最小值、平均值和变化速率。
- 支持选择一个时间区间。
- 支持将选中区间和相关点位发送给 Agent。
- Agent 可以创建临时关注组和诊断标记。
- Agent 的结论可以绑定到具体曲线区间。
- 支持导出选中区间数据。
- 每个样本保留质量，坏质量区间不能被曲线插值伪装成正常连续数据。
- R1 先保留内存短窗口；持久历史、压缩和长期保留策略放入 R2，避免在多连接模型稳定前引入数据库复杂度。

### 9.5 写点

- 只允许写入 `access:writable` 的 `coil` 或 `holdingRegister` 点位。
- 单点线圈写使用 FC05，单点保持寄存器写使用 FC06；点位配置仍保留读功能 FC01/03，日志必须显示实际写功能码。
- 写入前显示连接、端点、设备、Unit ID、点位、地址、当前值、目标值、单位和工程范围。
- 对越界、类型不匹配、坏质量、端点漂移、设备停用和连接断开分别给出可读错误。
- 用户直接写入和 Agent 请求写入都进入时间线，携带完整对象 ID 和端点指纹。
- Agent 发起写点必须由用户确认；确认卡绑定配置版本和端点指纹，过期或目标变化后失效。
- 写入后自动回读，最终状态区分“协议写成功且回读一致”“协议写成功但回读不一致”“协议失败”“无法回读”。
- R1 不做批量写入；R2 再增加 FC15/16，并单独设计影响范围预览和部分失败处理。

### 9.6 告警与异常

- 点位可配置高高、高、低、低低或简单变化速率阈值，并配置死区与触发延时。
- R1 至少支持激活、恢复和确认三个状态，事件保存优先级、首次发生、最后发生、恢复时间和确认来源。
- 通信故障和过程报警分开呈现，防止端口断线产生大量虚假的点位越限。
- 异常在表格和曲线中按所属连接/设备高亮，重要事件进入时间线。
- 当前绑定 Session 接收去重后的摘要；重复报警按抑制窗口合并，避免连续轮询刷屏。
- Agent 按需查询异常前后的点值、质量、报文和最近操作。
- 初期只做本地规则和历史，不建设企业级报警路由、排班通知或复杂规则引擎。

## 10. Session Agent 联动规划

### 10.1 台架模式预设

安装插件后提供「台架模式」预设。该预设应让 Agent 明确知道：

- 它正在一个真实设备台架环境中工作。
- 当前工程、连接和设备状态必须通过工具确认。
- 调试页和上位机页是用户可直接操作的现场界面。
- 界面选择和时间线事件是可靠的用户现场上下文。
- 大量数据应按需查询，不能要求全部进入系统提示。
- 写点、下载、复位等操作需要遵守人工确认规则。
- 诊断结论必须引用实际证据。

预设本身只提供稳定规则和工具能力，不持续塞入高频实时数据。

### 10.2 当前 Session 绑定

界面需要明确展示：

- 当前是否有 Session。
- 当前 Session 是否使用台架模式。
- 当前台架事件将通知哪个 Session。
- 当前是否存在 Agent 正在执行的台架任务。

建议交互：

- 新建并选择台架模式 Session 后自动绑定。
- 用户可以手动将当前 Session 绑定或解绑台架。
- 切换 Session 后，主动通知只发送给新的当前绑定 Session。
- 已经运行的任务继续保留原始发起 Session 归属。

### 10.3 Agent 获取现场信息

Agent 能查询：

- 当前台架总览。
- 当前工程、Target 和产物。
- 最近编译和下载记录。
- 编译错误与完整日志。
- 串口最近日志和指定时间范围。
- Modbus 连接列表、端点租约、健康状态和当前界面焦点。
- 指定连接下的设备/Unit ID 和轮询状态。
- 指定设备的点表、Qualified Value 和状态快照。
- 指定连接的报文、事务详情和通信统计。
- 指定曲线时间范围的数据摘要。
- 最近时间线事件。
- 当前等待确认或人工操作的任务。

### 10.4 重要事件主动通知

以下事件可以通知当前绑定 Session：

- 用户切换工程或 Target。
- 编译完成或失败。
- 下载完成或失败。
- 设备连接、断开或重启。
- 串口发现新的严重错误或断言。
- Modbus 连接状态变化或连续通信失败（携带 `connectionId`）。
- 单一设备离线、恢复或 Unit ID 响应异常（携带 `deviceId`）。
- 监控点超过已配置阈值（携带 `pointId`）。
- 用户向 Agent 发送日志、连接、设备、点位、报文或曲线区间。
- 用户完成 Agent 请求的人工步骤。
- Agent 发起的后台任务完成。

通知只包含摘要和查询线索，不包含完整大数据。

### 10.5 用户从界面发给 Agent

调试界面提供：

- 发送当前工程。
- 发送选中的编译错误。
- 发送完整编译记录。
- 发送选中的串口日志。
- 发送固件产物和下载结果。

上位机界面提供：

- 发送连接状态和通信统计。
- 发送设备/Unit ID 与配置摘要。
- 发送点位。
- 发送监控分组。
- 发送选中的请求/响应报文。
- 发送设备状态快照。
- 发送曲线选区。
- 发送异常事件及其前后数据。

发送时应生成结构化引用，而不是只复制一段文本。引用至少包含对象类型、稳定 ID、配置版本、时间范围和可复查的查询参数。

### 10.6 Agent 操作回到界面

Agent 发起的操作必须在传统界面中可见：

- 显示操作来源为 Agent。
- 显示关联 Session。
- 显示执行进度。
- 显示参数和结果。
- 支持用户取消。
- 需要确认时在界面出现明确卡片。
- 失败时提供“回到 Session 查看分析”。

Agent 还可以请求界面执行以下呈现行为：

- 打开调试页或上位机页。
- 聚焦某次编译记录。
- 高亮某条错误。
- 高亮某个点位。
- 切换到指定连接和设备。
- 打开并高亮指定报文或请求/响应事务。
- 展示某段曲线范围。
- 创建临时监控分组。
- 展示需要用户执行的人工步骤。

Agent 可以创建连接、设备或点位的“变更草稿”，但不能在后台静默应用。界面必须展示差异、冲突校验和影响范围，由用户确认后写入共享状态。

### 10.7 人工操作请求

Agent 不能自动完成的现场动作，应通过结构化请求交给用户：

- 连接或断开硬件。
- 上电或断电。
- 按下复位键。
- 切换拨码开关。
- 确认设备型号或指示灯状态。
- 确认是否允许下载、写点或复位。

请求状态包括：等待、已完成、已拒绝和已取消。用户完成后，Agent 能继续原来的流程。

## 11. Agent 工具能力规划

初期继续保留 `corn_bench` 作为统一入口，避免一次安装向模型暴露过多零散工具。能力增多后，再根据 schema 大小和使用效果决定是否拆分。

规划中的能力分组如下。

### 11.1 只读能力

- 查询台架总览和当前界面焦点。
- 查询当前 Session 绑定状态。
- 列出工作区资源。
- 查询工程和 Target。
- 查询编译记录、错误和日志。
- 查询固件产物。
- 查询连接列表、端点占用和连接健康。
- 查询指定连接下的设备/Unit ID。
- 查询指定连接的报文、事务详情与统计。
- 查询串口日志。
- 查询指定设备的点表和 Qualified Value。
- 查询采样数据和曲线摘要。
- 查询时间线事件和证据引用。

### 11.2 普通操作能力

- 选择工程和 Target。
- 发起编译。
- 取消编译。
- 创建连接/设备/点位变更草稿。
- 创建临时监控分组。
- 创建设备状态快照。
- 发起定向只读验证步骤。
- 请求用户完成现场操作。
- 请求界面聚焦连接、设备、点位、报文或曲线区间。

### 11.3 受控高影响能力

- 下载固件。
- 复位设备。
- 应用连接、设备或点位配置草稿。
- Modbus 写点（必须使用 `pointId` 定向，根据数据区执行 FC05/06，并进行回读）。
- 发送可能改变设备状态的串口命令。

这些能力必须返回待确认内容，由用户在界面中批准后执行。

### 11.4 工具参数契约

- 多连接版本上线后，`read/write/frames/device/status` 等涉及现场对象的操作不得依赖隐式“当前连接”。
- 写入最少要求 `connectionId + deviceId + pointId`；临时裸地址读取必须显式提供 `connectionId + deviceId + area + address + count`。
- 返回值统一携带 `workspaceId/sessionId/taskId`，现场对象按需携带 `connectionId/deviceId/pointId/frameId`。
- 错误返回稳定错误码和可读中文信息，例如 `PORT_IN_USE`、`DEVICE_DISABLED`、`STALE_VALUE`、`ENDPOINT_DRIFT`、`WRITE_READBACK_MISMATCH`。
- 高影响操作的批准必须绑定请求哈希、端点指纹和配置版本，批准不能被另一条连接或另一个点位复用。

## 12. 台架时间线与证据

### 12.1 事件类型

至少记录：

- 工程选择。
- Target 选择。
- 工具绑定变化。
- 编译开始、完成、失败和取消。
- 产物生成。
- 下载开始、完成、失败和取消。
- 设备连接、断开、复位和重启。
- 串口严重日志。
- Modbus 连接变化。
- 点位读取异常。
- 点位写入和回读。
- 曲线区间选择。
- 用户发送现场内容给 Agent。
- Agent 发起操作。
- 用户批准、拒绝或取消。
- Agent 诊断结论。
- 验证步骤通过或失败。

### 12.2 每条事件的公共字段

- 唯一事件 ID。
- 时间。
- 工作区。
- 来源类型和来源名称。
- 关联 Session。
- 关联任务。
- 事件摘要。
- 结构化详细数据。
- 相关附件或日志定位。
- 操作结果。
- 可选的 `connectionId/deviceId/pointId/frameId`。
- 事件发生时的端点、Unit ID、点位名称等只读摘要，保证对象后来被删除后仍可解释。
- 证据引用列表，例如请求报文、响应报文、日志区间、曲线区间和写入回读结果。

### 12.3 界面表现

- 按时间倒序展示。
- 支持按编译、下载、通信、Agent 和异常筛选。
- 支持从事件跳转到对应界面对象。
- 支持从事件打开关联 Session。
- 支持选中多条事件发送给 Agent。

## 13. 本地测试闭环

在传统功能和 Agent 联动稳定后，增加轻量的本地验证流程，不建设团队级测试平台。

### 13.1 验证步骤

支持以下步骤：

- 编译指定工程和 Target。
- 确认指定格式产物存在。
- 下载固件。
- 等待设备上线。
- 等待串口关键字。
- 读取一个或多个 Modbus 点位。
- 判断点位是否在范围内。
- 持续采样一段时间。
- 请求用户完成一个人工步骤。
- 生成通过或失败结论。

### 13.2 验证流程示例

```text
1. 编译当前 Release Target
2. 确认 HEX 产物生成
3. 请求用户确认下载目标设备
4. 下载固件并复位
5. 等待串口出现启动完成标记
6. 读取设备版本寄存器
7. 对比设备版本与当前固件版本
8. 连续读取关键点位 30 秒
9. 判断通信和数值是否正常
10. 输出带证据的验证结果
```

### 13.3 结果输出

- 每一步开始、结束和耗时。
- 输入参数。
- 实际结果。
- 通过或失败。
- 对应日志、点位和产物。
- Agent 总结。
- 可导出的本地 Markdown 报告。

## 14. Windows 部署功能

### 14.1 安装与首次配置

- 检测 Windows 和 Node.js 环境。
- 检查 Python、Keil UV4、OpenOCD 路径。
- 检查 Python 依赖。
- 检查常用串口驱动和可见串口。
- 显示 Windows 设备友好名称、COM 号、VID/PID 和当前是否被本插件占用；无法可靠识别外部占用时，在实际打开端口后给出明确失败信息。
- 检查台架模式预设是否可用。
- 提供一页首次配置向导。
- 配置完成后运行一次只读自检。

### 14.2 环境诊断

提供“台架自检”功能，检查：

- 插件 Host 和 Client 是否加载。
- 当前 Session 是否能调用台架工具。
- 本机程序是否存在并可启动。
- Python 依赖是否齐全。
- 工作区是否可访问。
- 串口是否存在、是否能打开、是否被本插件其他连接占用、是否疑似被外部程序占用。
- 每条 Modbus 连接是否可建立，设备 Unit ID 是否响应，串口参数不匹配时是否给出超时/CRC/帧错误区分。
- 调试器是否可识别。

Windows 正式验收不得由 macOS 仿真代替。至少需要在 Windows 10/11 上验证：COM1–9、COM10+、USB 串口拔插、端口被其他软件占用、两条不同 COM 并发、服务端监听端口冲突和应用重启后的资源释放。

诊断结果可以直接发送给 Agent。

### 14.3 本地数据位置

本地数据应清楚分为：

- 全局工具绑定。
- 每工作区设置。
- 点表。
- 编译和下载记录。
- 串口与采样数据。
- 时间线和验证报告。

界面需要提供“打开数据目录”和“清理历史记录”，但不能默认删除工程文件和固件产物。

## 15. 典型联动流程

### 15.1 编译失败后由 Agent 修复

```text
用户在调试页点击编译
→ 插件创建编译任务并记录来源
→ 编译失败，界面显示结构化错误
→ 当前 Session 收到失败摘要
→ Agent 查询完整错误和相关日志
→ Agent修改代码
→ Agent 发起重新编译
→ 调试页显示“由 Agent 发起”及进度
→ 编译成功并生成产物
→ Agent给出修改与验证结论
```

### 15.2 用户把曲线异常交给 Agent

```text
用户在上位机曲线上选择异常区间
→ 点击“让 Agent 分析”
→ 插件创建曲线区间引用并发送给当前 Session
→ Agent 查询同期相关点位、串口日志和最近操作
→ Agent 在曲线上添加异常标记
→ Agent 给出可能原因和下一步验证建议
→ 用户决定是否执行验证
```

### 15.3 Agent 请求下载并验证

```text
Agent 完成代码修改和编译
→ Agent 发起下载请求
→ 调试页显示 Target、产物、哈希和目标设备
→ 用户批准
→ 插件下载、校验并复位设备
→ 插件等待启动日志并读取版本
→ Agent 汇总下载和运行验证结果
```

### 15.4 Agent 请求人工现场操作

```text
Agent 判断需要重新上电
→ 界面出现“请断电后重新上电”的任务卡
→ 用户完成并点击确认
→ 事件写入时间线
→ Agent 收到完成通知并继续读取设备状态
```

### R1：标准上位机骨架——连接、设备、点位、报文

目标：结束单连接模型，建立不会阻碍后续功能的正确领域结构。

范围：

- `version:3`：`connections[] + devices[] + points[] + QualifiedValue[]`。
- v2 → v3 可恢复迁移和迁移报告。
- 连接管理器与端点资源锁。
- 连接下多 Unit ID 设备层。
- 点位稳定 ID、所属设备和数据区语义。
- 多连接轮询、连接级报文分轨、请求/响应配对和基础通信统计。
- Tool/Host 的 `connectionId/deviceId/pointId` 契约。
- 单点 FC05/06 写入、确认和回读。

成功门槛：

- 两条不同 COM 可以并行；同一 COM 冲突被阻止且不影响其他连接。
- 同一 RTU 连接下两个 Unit ID 可以配置同地址点位，数值、报警、趋势和写入互不串扰。
- TCP 客户端同一远端端点不会被错误标记为本地端口占用；TCP 服务端监听冲突会被阻止。
- 所有点值能追溯到连接、设备和来源报文。
- 旧工作区迁移后读写语义不变，重复加载 ID 稳定。
- 自动化测试全绿、生成客户端一致，Windows 多 COM 手工验收通过。

明确不进入 R1：长期历史数据库、批量写入、设备扫描、复杂报警、图形化画面编辑器。

### R2：日常调试效率——点表、趋势、报警和诊断

目标：在正确模型上补齐传统上位机的高频维护能力。

范围：

- 数据类型、字节序/字序、位域、比例、单位和枚举。
- CSV/JSON 导入校验预览、设备级模板文件和批量编辑。
- 多轮询组、质量/陈旧状态、断线恢复。
- 报文过滤、导出、延迟/超时/异常码统计。
- 短期历史、趋势选区、快照对比。
- 本地报警确认、恢复、死区、延时和去重通知。

成功门槛：用户不使用 Agent，也能完成一台真实设备从建连接、建点表、找通信故障到导出证据的完整流程。

### R3：Session Agent 深度联动

目标：让当前 Session Agent 成为共享工作台中的可见协作者。

范围：

- 所有界面对象的“让 Agent 分析”。
- Agent 定向查询连接、设备、点位、报文、趋势和报警。
- Agent 驱动界面聚焦、证据高亮和临时监控组。
- 配置变更草稿与界面差异确认。
- 写入、下载、复位统一高影响审批。
- 任务完成、设备离线和报警的去重主动通知。

成功门槛：Agent 的每个现场结论都能跳转到证据；Agent 的每个现场操作都能在界面中看到目标、进度、结果和来源。

### R4：Windows 正式版与本地闭环

目标：完成真实 Windows 台架上的稳定安装、升级和验证闭环。

范围：

- 首次配置向导、环境诊断、COM 设备识别和数据目录管理。
- 编译—下载—启动日志—点位验证流程。
- Markdown 验证报告。
- 工作区备份、迁移失败恢复和升级兼容。
- Windows 10/11 真实硬件验收与发布清单。

成功门槛：在全新 Windows 环境安装后，用户能在 Agent 监督但不依赖 Agent 的前提下完成一次真实设备验证，并在重启后恢复工程、连接、设备、点表、时间线和未清理的证据。

## 17. 验收场景清单

正式版本至少覆盖以下真实场景：

1. 首次安装后创建并选择台架模式 Session。
2. 绑定 Windows Python、Keil UV4 和 OpenOCD。
3. 选择工程和 Target，完成一次成功编译。
4. 产生编译错误，将错误发送给 Agent 并重新编译。
5. 选择固件并完成一次用户确认后的下载和验证。
6. 连接串口并把一段错误日志发送给 Agent。
7. 创建 RTU 客户端连接并选择 COM、串口参数，连接成功。
8. 在同一 RTU 连接下添加两个不同 Unit ID，并为二者创建相同地址的点位。
9. 创建第二条不同 COM 的连接并并行轮询，两条连接数据和报文互不串扰。
10. 尝试把第二条已启用连接配置到相同 COM，界面和运行时均阻止冲突。
11. 串口被第三方软件占用时显示明确错误，释放后可以重试连接。
12. COM10+ 可以正常识别和打开；USB 串口拔出后状态变为 disconnected/stale，重新插入后可恢复。
13. TCP 客户端连接多个 Unit ID；TCP 服务端监听端口冲突被阻止。
14. 导入点表并连续监控多个数据类型和字节序点位。
15. 错误串口参数、超时、Modbus 异常响应和 CRC/帧错误在报文分析器中可区分。
16. 在曲线上选择一个区间并让 Agent 分析，坏质量区间不会伪装成正常连续数据。
17. 由 Agent 使用明确的连接、设备和点位 ID 发起一次读取。
18. 由 Agent 请求一次写点，用户拒绝后不产生设备修改。
19. 由 Agent 请求写线圈和保持寄存器，用户批准后分别通过 FC05/06 完成回读验证。
20. 写入批准后端点或配置发生变化，请求失效且不能写向新目标。
21. 设备断开后，界面和当前 Session 都得到一致且去重的状态通知。
22. 用户从报文窗口把一个请求/响应事务发送给 Agent，Agent 能引用同一证据返回分析。
23. Agent 请求用户完成一次重新上电操作并在确认后继续。
24. 从时间线回看完整的问题处理过程，对象删除后旧事件仍可解释。
25. 导出一份包含产物、日志、连接、设备、点位、报文和结论的验证报告。

### 17.1 自动化与人工证据分离

- 自动化门槛：单元测试、迁移测试、并发锁测试、工具契约测试、生成客户端一致性和构建检查。
- Windows 人工门槛：真实 COM、真实 USB-RS485、端口占用、拔插、双 COM 并发、真实 Unit ID、真实写入回读。
- Agent 人工门槛：界面对象发送、Agent 定向查询、界面聚焦、审批卡目标核对和证据跳转。
- 自动化全绿不能代替 Windows 硬件、界面交互或 Agent 联动验收；未执行项必须在发布记录中明确列出。

## 19. 最终产品形态

完成本规划后，`dsh-corn-bench` 应具备以下体验：

- 用户打开 Windows 上的 DeepSeek Harness，进入一个工程 Session。
- 调试页和上位机页已经掌握当前工程、设备和连接状态。
- 用户可以像使用传统工具一样完成编译、下载、看日志和监控点位。
- 用户可以按连接、设备/Unit ID 和点位理解现场，并按连接查看真实通信报文。
- 当前 Session 的台架模式 Agent 能随时查询同一份现场。
- 重要变化会以摘要通知 Agent，详细数据由工具按需获取。
- 用户可以把错误、日志、点位和曲线选区直接交给 Agent。
- Agent 的编译、查询、验证和请求会在传统界面中清晰呈现。
- 写点、下载和复位始终由用户掌握最终决定。
- 整个问题处理过程被时间线和证据串联起来。

最终目标可以概括为：

> 在一台 Windows 电脑上，把传统嵌入式调试、上位机监控和当前 Session Agent 变成同一套工作流，而不是三个互相隔离的工具。

## 20. 外部产品与规范基线

本规划采用以下可复查基线，不以单一竞品界面作为照抄目标：

- [Modbus Serial Line 规范](https://www.modbus.org/file/secure/modbusoverserial.pdf)：串行总线由客户端/主机发起请求，同一总线可包含多个服务端/从站；因此需要 Connection 下的 Device/Unit ID 层。
- [Microsoft Communications Resource Handles](https://learn.microsoft.com/en-us/windows/win32/devio/communications-resource-handles)：Windows 串口以独占方式打开；因此必须同时做工程级 COM 冲突提示和运行时资源锁。
- [Rapid SCADA Device Polling](https://rapidscada.net/docs/en/latest/configuration/device-polling)：通信线独立并行，设备归属于通信线；支持本规划的连接—设备层级和故障隔离。
- [Modbus Poll](https://www.modbustools.com/modbus_poll.html)：多监视窗口、数据格式、串行流量、日志和实时曲线是传统调试工具的基础能力。
- [Modbus Tester](https://github.com/manne2400/Modbus_Tester_Emulator)：并行会话、标签、帧分析、延迟/超时统计、快照和导入导出可作为 R2 体验参考。
- [ModbusLens](https://github.com/CraftParking/ModbusLens)：连接级原始报文、标签监视、趋势、服务端模拟和受限测试序列证明“传统工具 + 可重复诊断”可以共存。
- [Ignition Tag Diagnostics](https://www.docs.inductiveautomation.com/docs/8.3/platform/tags/tag-diagnostics)：点值应包含当前值、质量、时间戳和诊断信息，而不是只保存最后一个数值。
- [ISA-101](https://www.isa.org/standards-and-publications/isa-standards/isa-standards-committees/isa101) 与 [ISA-18 报警管理](https://www.isa.org/intech-home/2018/march-april/features/alarm-management-life-cycle)：界面导航、动态元素、报警、历史和审计需要一致且可追溯。

X 的公开检索在本轮没有得到足够稳定、可复查的工程帖子，因此不作为功能决策证据。后续只有在获得具体帖子或账号时再纳入补充研究。
